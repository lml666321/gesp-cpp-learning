# CSP-J 互动学习

以 CSP-J 为核心的 C++ 互动学习网站，沿用原有 GESP 基础内容与目录结构。副标题：C++ 基础 · 算法思维 · 编程实践。

- 在线地址：https://lml666321.github.io/gesp-cpp-learning/
- 项目仓库：https://github.com/lml666321/gesp-cpp-learning
- 本地入口：`GESP_Unit1_Interactive_Demo/index.html`

## 已开放内容

- 单元 01「程序基础与数据表达」：8 节、16 道课内题、14 道章节题、智能温室综合挑战。
- 单元 02「条件分支与程序决策」：6 节、12 道课内题、8 道章节题、成绩分类器与边界测试综合挑战。
- 每节保持「认识与实验 → 自己试 → 应用挑战 → 本节小结」。允许预览；新版完成记录要求实验达标、两题答对、确认小结。
- 每单元有独立学习报告；章节练习保存每次选择、错题对应知识点、每轮成绩及未完成的一轮。
- 首页提供“继续上次位置”和“推荐下一步”，并按阶段展示完整学习路线。
- 学前准备及单元 03～14 仅有简介、先修关系与“规划中”状态，没有虚构已上线课程。

路线依据本地 `NOI_Syllabus_Edition_2025.pdf` 正文第 9～18 页的 2.1 入门级范围编排，路线名称为教学编排，不是官方原始章节名称。数学按先修需要穿插，指针、引用、线性筛、哈夫曼树和简单区间 DP 保留在规划范围中。本轮不涉及具体年份考试安排或规则。

## 本地使用与模拟边界

直接双击 `GESP_Unit1_Interactive_Demo/index.html`，无需安装依赖或联网加载资源。网页也可由普通静态服务器提供。没有登录、教师后台、云端同步或真实在线判题。

实验只模拟界面展示的固定程序，不支持执行任意 C++。整数实验会校验完整输入、空值、小数、非有限值、范围与零除数；它不模拟 `cin` 对小数文本的部分读取。各实验标明输入范围，以避免整数溢出或 JavaScript 与 C++ 数值范围差异造成误导。字符题使用 ASCII 编码。

智能温室挑战的“四项要求检查”是选项检查，并非四组测试数据。单元二挑战可输入 `分数:预期输出` 测试清单，逐行展示预期、题意输出和模拟输出；仅针对固定分类模板。修改选项后结果失效，失败重做不会取消历史完成记录。

## 学习记录与兼容

继续使用原 localStorage key：`gesp-unit1-demo-v2`，内部结构升级为 `schemaVersion: 3`。

- 单元、知识点、章节、题目分别使用稳定 ID，例如 `u2`、`u2-l1`、`u2-c1`、`u2-l1-q1`。展示序号不作为跨单元身份。
- 原 `completed`、`attempts`、`hints`、`chapterScores`、`challengePassed`、`lastLesson` 会迁移到单元一，旧数据同时保留；原知识点 1～8 映射为 `u1-l1`～`u1-l8`。
- 旧版没有步骤或逐题证据。报告将旧完成、旧总尝试与提示次数注明为历史记录，不虚构首次答对、实验完成或错题；旧 `lastLesson` 恢复到相应知识点的认识与实验。
- 新记录保存实验路径、已访问步骤、已完成步骤、每题尝试、提示/完整解析使用、首次答对的具体条件、小结确认、章节轮次、挑战历史最佳与本次结果。
- 查看同一课内题的提示只记录一次；“首次答对”“未查看提示”是行为记录，不等同于全面掌握。
- 单元一与单元二记录隔离；报告可以重置本单元或全部本机记录，均有明确的清除确认。失败重做不会降低历史完成进度。
- 不同设备、浏览器，以及本地文件和在线网址之间不会自动同步。清理网站数据或更换本地文件路径可能影响记录访问。存储不可用时页面会提示，当前会话仍可学习。

## 本地验证

网页运行不依赖 Node 或编译器；以下只用于维护时测试。

```sh
node --check GESP_Unit1_Interactive_Demo/app.js
node --check GESP_Unit1_Interactive_Demo/data/lessons.js
node --check GESP_Unit1_Interactive_Demo/data/questions.js
node tests/content-check.cjs
node tests/site-regression.cjs
```

内容检查需要 C++17 编译器，默认 `clang++`，可用 `CXX` 指定。浏览器检查需要 Playwright；可用 `NODE_PATH` 指向已有依赖目录，用 `CHROME_PATH` 指定 Chrome/Chromium。macOS 默认使用 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`。Codex 内 Node 不在 PATH 时可查询工作区运行依赖路径，无需给网站添加 npm 依赖。

浏览器回归覆盖所有 14 节实验、课内题逐选项反馈、四组章节练习、两种综合挑战、报告、刷新恢复、旧数据迁移、单元隔离、重置、输入边界、结果失效和快速切页；同时检查 `file://`、与发布包一致的五文件 HTTP 站点、桌面与 390/320px 手机视口。截图写入系统临时目录 `csp-learning-tests`，可用 `CSP_TEST_ARTIFACTS` 改位置。测试不操作真实浏览器的学习记录。

## 发布与更新

GitHub 仓库使用免费公开仓库和 GitHub Pages。`.github/workflows/pages.yml` 在 `main` 的网页或部署配置发生变化时发布；推送会触发上线。

网页变更应先完成本地实施与验证，经用户确认后再推送上线。

部署仍只打包原有五个网页文件，未新增网页资源，故本轮无需修改发布清单。测试脚本加入 `.gitignore` 允许清单用于维护，但不会进入站点发布包。发布前检查 Git 状态并明确选择待提交文件；不要加入本地原始资料或覆盖协作者改动。

需要恢复旧版时，对相应修改创建还原提交，经确认后推送；不要覆盖根目录的历史 HTML。
